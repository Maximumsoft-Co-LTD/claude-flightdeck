# Index Discipline — token-friendly file creation workflow

> Rule **L154** — auto-loaded via CLAUDE.md.
> Purpose: every large living document (sprint, backlog, design-doc collection) has a sibling slim INDEX file. Skills that read these files should prefer the index; skills that mutate them must refresh the index same-commit.

## Why

Large markdown tables with a wide notes column are the #1 per-invocation token sink. A 40-line slim index answers the same "what is the next task?" question in ~1 K tokens vs the full-file Read of ~4 K. It compounds across `/work`, `/status`, `/retro`, `/document`.

Typical measured savings:
- `/work`: ~5 K → ~1.5 K
- `/status`: ~14 K → ~4 K
- `/retro`: ~18 K → ~6 K

## The four index files

| Index | Companion to | Shape | Max size | Consumer |
|---|---|---|---|---|
| `docs/project/sprints/XX/tasks.md` | `sprint-XX.md` | 4-col: ID \| Component \| Status \| Depends | ~60 lines | `/work` Step 1, `/status`, `/retro` |
| `docs/project/sprints/XX/designs/INDEX.md` | the dir of `DXXX-*.md` | 4-col: DXXX \| Title \| Status \| Task-ID | ~30 lines | `/work` Step 7, `/document` |
| `docs/project/backlog-index.md` | `backlog.md` | derived counts (open · wip · sprints) — **regenerated by `scripts/backlog.sh index`, never hand-edited** | ~12 lines | `/work` Step 1 (sprint resolver), `/idea promote`, `/retro archive` |
| `docs/project/sprints/INDEX.md` | the dir of `sprint-*.md` | 3-col: Sprint \| Status \| Dates | ~30 lines | `/retro archive`, humans orienting |

## The hot/cold split — backlog archive sweep

> **Why this exists.** A slim index keeps the *read* cheap; this keeps the
> *backlog itself* cheap. `backlog.md` is a **hot** file — `/work`, `/status`,
> and `/retro` read it constantly, so every closed row left in it is paid for on
> every read. Closed work that never leaves `## Active` is the #1 way a backlog
> silently grows to thousands of lines (one real project reached **316 KB**). The
> fix is a one-way sweep into a **cold** archive that is *grepped on demand, never
> loaded wholesale*.

> **Why the Status enum is part of this.** The split only works if "terminal" is
> *machine-decidable*. The companion failure mode is a Status cell that becomes a
> free-text *log* (`discovery → verified → …done` buried mid-cell) — then no grep
> can tell open from done, and `/work` re-picks shipped work. So Status is a
> **single token** from a closed enum, delivery-lifecycle only (design-review
> state lives in `designs/INDEX.md`, never the backlog):
>
> | Where | Allowed Status |
> |---|---|
> | `## Active` (hot) | `open` · `wip S<N>` |
> | cold archive (terminal) | `done S<N>` · `wontfix` · `superseded-by B###` |

**The rule:** `## Active` holds **only `open` / `wip S<N>` rows.** The moment a
row reaches a terminal status (`done S<N>`, `wontfix`, `superseded-by B###`), it is
swept into the cold ledger. The sweep is **mechanical** — `scripts/backlog.sh
sweep` (run by `/retro`), not hand-curation:

| File | Role | Shape | Budget | Loaded? |
|---|---|---|---|---|
| `docs/project/backlog.md` `## Active` | hot working set | open rows only | small | every `/work` |
| `docs/project/archive/backlog-archive.md` | cold ledger | one line per closed item | **1,000 lines → rotate** | grep on demand only |

**Why the archive doesn't just re-bloat** (the obvious objection):

1. **It's cold.** Never Read wholesale into context — only `grep '<ID>'
   archive/backlog-archive.md`. Growth there costs ~nothing per task; the pain was
   always in the *hot* file you Read every task.
2. **It's thin.** One line per item. The full detail (Source / AC / sub-tasks)
   already lives in `sprints/sprint-NN-*.md`, `ideas/D<NNN>-*.md`, and git history
   — never duplicated into the archive.
3. **It rotates.** Past the line budget, roll the oldest sprints into
   `backlog-archive-2.md` (then `-3`, …). No single file grows unbounded.

**One script, four call-sites** (mechanism, not vigilance) — `scripts/backlog.sh`
(pure bash, 0 LLM tokens) — so the backlog is **synced at every point work
touches it**, not just at sprint close:
- **`/work` pick** runs `verify <B###>` before executing — exit 1 = already closed
  (cold archive, terminal, or a sprint board marks it `[x]`), so it never
  re-implements shipped work (the re-pick cure).
- **commit-time** — `install-hook` writes a git `pre-commit` gate: any commit that
  stages `backlog.md` runs `check`, so a drifted/bloated backlog **cannot be
  committed** (this is the "always-synced" guarantee; `--no-verify` overrides).
- **`/retro` sprint-close** runs `reconcile` → `sweep` → `index` (retro SKILL Mode 1).
- **Shipped CI** runs `check`: fails the PR if any `## Active` Status is not
  `open`/`wip S<N>` — catching **both** drift directions (a terminal row left in
  Active *and* a mislabeled blob like `verified`/`discovery`) — plus a **hard size
  cap** (lines + bytes) so the hot file can't grow back to 316 KB.

## Creation workflow (MANDATORY)

### Creating a new sprint

1. `docs/project/sprints/XX/tasks.md` — full file
2. `docs/project/sprints/XX/tasks.md` — **sibling, same commit**
3. Append one row to `docs/project/sprints/INDEX.md`
4. Update `docs/project/backlog-index.md`

### Creating a new design-doc directory

1. `docs/project/sprints/XX/designs/DXXX-name.md` — full file
2. First design doc in a new dir: create `docs/project/sprints/XX/designs/INDEX.md`
3. Every subsequent design doc: **append one row** to INDEX.md same commit

### Mutating any of these files

| You change | You MUST also update | Same commit? |
|---|---|---|
| `sprint-XX.md` task-row status | `sprint-XX-index.md` row | Yes |
| Add a new `DXXX-*.md` | `docs/project/sprints/XX/designs/INDEX.md` row | Yes |
| Close a sprint in `backlog.md` | `backlog-index.md` + `docs/project/sprints/INDEX.md` | Yes |
| A `## Active` row reaches terminal status | `scripts/backlog.sh sweep` + `index` (keeps `## Active` open/wip-only) | Yes (at sprint close) |

## Staleness detection

```bash
stat -f '%m' sprint-XX-index.md sprint-XX.md
# index mtime < full-file mtime → warn + read full file (indexes are derived from the board/backlog — no manual refresh needed)
```

## Index refresh

Indexes are derived from the board/backlog — no manual refresh command is needed. Skills that mutate sprint/backlog files must update the sibling index in the same commit.
