# /document — Generate / Sync Project Documentation

Generate user-facing or contract-facing documentation from the source
of truth (live system, OpenAPI / proto / GraphQL schema, in-repo
design docs, or screenshots from a real browser). The skill picks the
right source for the request and loads the matching variant
reference.

## Token budget (MANDATORY)

- Use Grep to discover existing docs before regenerating — don't
  rewrite what's already there.
- Read the live spec / contract / schema as the canonical source.
- For UI screenshots, drive a real browser (Playwright MCP) — never
  trust a curl response for SPA pages.

## Usage

- `/document` — full sync (regenerates everything in scope)
- `/document <module>` — sync one module / endpoint group / feature
- `/document status` — show coverage (documented vs existing)
- `/document refresh` — re-capture + update existing pages
- `/document export` — emit deployable artifact (SQL seed / static
  site / SDK package)

## Prerequisites check

Before any generation step, verify:
1. The source-of-truth is reachable (live service / spec file / repo).
2. If screenshots are part of the output: the frontend + backend are
   running, and Playwright MCP is available.
3. Output directory exists and is writable.

If any prerequisite fails → tell the user what's missing and stop.

## Steps

### 1. Discover scope

`Glob` existing docs; `Grep` the source of truth; compute the diff
(what's documented vs what exists). Read `docs/.manifest.json` (or the
per-scope manifest) to know what was generated by which tool.

### 2. Pick the right variant — load the matching reference

| If the source is... | Load before generating |
|---|---|
| `contracts/openapi/*.yaml` or `*.json` | `references/api-openapi.md` |
| `contracts/proto/**/*.proto` (or `proto/**`) | `references/api-proto.md` |
| The live UI (screenshots / walkthrough) | `references/user-guide-playwright.md` |
| The contract → SDK code (any language) | `references/sdk-codegen.md` |
| Always (for the manifest schema + refresh logic) | `references/manifest-format.md` |

The variant reference is opinionated + concrete (real CLI invocations,
real config files, real failure modes). Inline the right one BEFORE
running any generator.

### 3. Generate

Run the tool per the variant reference. Output paths follow the
conventions in each reference + the manifest.

### 4. Idempotent writes

Every output file has a stable path; rerunning the skill updates
rather than appends. Manifest entries (`references/manifest-format.md`)
make this enforceable.

### 5. Verify

Sample the rendered output and confirm: links resolve, images embed,
sections match the contract. For SDKs, run the generated test
fixtures (`npm test` / `go test` / etc.).

### 6. Update the manifest

For each generated output, write/update its `docs/.manifest.json`
entry per `references/manifest-format.md`. Commit the manifest with
the outputs in the SAME commit.

### 7. Commit

`docs: regenerate <scope> from <source-of-truth>`. Include the
manifest update.

## Worked example — REST API docs

```
/document api v1
```

1. Discover scope → `contracts/openapi/v1.yaml` is the source; existing
   docs at `docs/api/v1.html`.
2. Load `references/api-openapi.md` + `references/manifest-format.md`.
3. Lint the spec: `npx @redocly/cli lint contracts/openapi/v1.yaml`.
4. Generate HTML + Markdown:
   ```
   npx @redocly/cli build-docs contracts/openapi/v1.yaml \
     -o docs/api/v1.html --title "MyAPI v1"
   npx widdershins contracts/openapi/v1.yaml -o docs/api/v1.md
   ```
5. Update `docs/.manifest.json` entry for `scope: api`.
6. Commit.

## Worked example — User guide screenshots

```
/document user-guide dashboard
```

1. Discover scope → `/dashboard` route in the FE app.
2. Load `references/user-guide-playwright.md`.
3. Confirm app is running locally (or use staging URL).
4. Run the capture script for `dashboard` across locales × themes ×
   widths.
5. Author `docs/user-guide/dashboard.md` with the captured screenshots
   embedded.
6. Update the manifest entry for `scope: user-guide`.
7. Commit.

## Worked example — SDK export

```
/document export ts
```

1. Source = `contracts/openapi/v1.yaml`.
2. Load `references/sdk-codegen.md` + `references/manifest-format.md`.
3. Run:
   ```
   npx @openapitools/openapi-generator-cli generate \
     -i contracts/openapi/v1.yaml -g typescript-fetch -o sdk/ts \
     --additional-properties=npmName=@myorg/api-sdk,packageVersion=1.1.0
   ```
4. Build + test the SDK locally.
5. Update manifest entry for `scope: sdk-ts` including `published:
   { registry: npm, package: @myorg/api-sdk, version: 1.1.0 }`.
6. Tag + publish (per the reference's publishing flow).
7. Commit.

## Worked example — Refresh all stale

```
/document refresh
```

1. Read `docs/.manifest.json`.
2. For each entry with `source_sha` ≠ current source SHA, regenerate
   via the matching variant reference.
3. For live-app sources (`scope: user-guide`), regenerate
   unconditionally (no SHA to compare).
4. Update + commit.

## Rules

- The **source of truth is canonical** — never hand-edit generated
  docs; edit the source and regenerate.
- Keep `manifest.json` (per `references/manifest-format.md`) in the
  output directory so refresh can reconcile state.
- Generated files must clearly say so in a header — readers should
  know not to hand-edit.
- For screenshot-based docs: SPA pages need a real browser; `curl`
  returns an empty shell and is forbidden.
- Always create docs in every required language / locale if the
  project is multi-lingual.

## When NOT to run this skill

- For Design Docs (`docs/designs/sprint-S<N>/D<NNN>.md`) — those are
  hand-curated by the `design-doc-writer` agent.
- For the sprint file / backlog / retro — those are owned by
  `/next-task` / `/promote` / `/retro` respectively.
